Loom is a software factory that runs on every AI subscription you have. It turns a goal into tickets, builds them in parallel, has them reviewed and fixed, ships them, and closes a ticket only when it shows up live and the goal's number moves.

The factory

GitHub is the conveyor belt.

Labels carry each ticket along. The brain, the station and you share nothing else.

loom:queued→ briefed→ running→ pr→ merged→ shipped→ verified
  1. 01
    GoalOne issue labelled loom:goal: what done looks like, how progress is measured, and the ship rules.
  2. 02
    BrainEvery tick it measures the goal, puts regressions first, ranks open problems by the goal's own measure, and writes tickets for the top ones.
  3. 03
    TicketWhy, What, and exactly three checks: one names a test that fails without the fix, one is the live proof.
  4. 04
    Station and lanesOnce a minute the station hands each ticket to a free lane: one agent CLI on one subscription, in its own clone and branch. Lanes never merge.
  5. 05
    Review by grugThe review bot and CI check every pull request. Findings go back to the lane that wrote it. Work that stays stuck climbs a ladder of stronger models.
  6. 06
    Merge, ship, verifyThe brain merges ready PRs and ships them under the project's rules. A ticket closes only when its proof shows up live and its metric moved.
  7. 07
    Journal and reportEach tick leaves a journal on the goal. Every two hours a short standup goes to your phone. You hear from it only when only you can act.

The rules
One ticket, one branch, one pull request. Lanes never merge.
Tests fail without the fix. Every bot comment is answered before merge.
Merged is not shipped, and shipped is not done.
Subscription CLIs run on your own login. No credential sharing.
Run it

Four steps on a Mac.

# 1. install on the lane machine bash lanes/mac/install.sh # 2. give each project a goal home issue labelled loom:goal # 3. point a brain at it: the installed tick, or Muse with docs/MUSE.md # 4. test python -B -m unittest discover -s tests -v
